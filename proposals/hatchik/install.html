Plug your AI into your Hatchik.

Paste one block of config into the AI tool you already use. From then on, your AI can ship code, check deploys, run migrations and roll things back — straight from chat. No CLI to learn.

Takes ~2 minutes. You'll need the API key from your Hatchik welcome email.

Which AI tool are you using?

Pick one. The steps are slightly different for each.

C

Connect Claude to Hatchik

Works with Claude Desktop on macOS and Windows, and with Claude Code.

1

Open the config file

If it doesn't exist yet, create it. The folder might be hidden — in Finder, press Cmd+Shift+. to show hidden files.

macOS
~/Library/Application Support/Claude/claude_desktop_config.json
Windows
%APPDATA%\Claude\claude_desktop_config.json
Claude Code (any OS)
~/.claude/mcp.json
2

Paste this in

Replace YOUR_HATCHIK_API_KEY with the key from your welcome email. If the file already has an "mcpServers" block, just add the "hatchik" entry inside it.

claude_desktop_config.json 
{
  "mcpServers": {
    "hatchik": {
      "command": "npx",
      "args": ["-y", "hatchik-mcp"],
      "env": {
        "HATCHIK_API_KEY": "YOUR_HATCHIK_API_KEY",
        "HATCHIK_API_URL": "https://api.hatchik.com"
      }
    }
  }
}
3

Restart Claude

Quit it completely (Cmd+Q on Mac) and reopen. Claude reads MCP servers on launch.

4

Test it

Start a new chat and type:

// You:
Are you connected to Hatchik? What project am I on?

Claude should reply with your project name, the domain you launched, and which region the server is in. If it says it doesn't know about Hatchik, the config didn't load — double-check the file path and that you fully quit and reopened the app.

What this does, in plain English: you're telling Claude that there's a service called "hatchik" it's allowed to talk to. When you ask Claude to ship a feature, check why the site is slow, or roll back yesterday's change, it can now do that directly — Claude calls our MCP server, our server checks your API key, and the action runs against your Hatchik project. Anything that costs money or could break things (payments, deletes, rollbacks) still bounces through your browser for a click-to-confirm.
Cu

Connect Cursor to Hatchik

Tested with Cursor 0.45 and later.

1

Open MCP settings

In Cursor: Cursor menu → Settings → Cursor Settings → MCP. Or open the command palette (Cmd+Shift+P) and search "MCP".

You can either click "Add new MCP server" in the UI, or edit the config file directly:

~/.cursor/mcp.json
2

Paste this in

Same shape as Claude — Cursor uses the same MCP standard. Replace the placeholder with your real key.

~/.cursor/mcp.json 
{
  "mcpServers": {
    "hatchik": {
      "command": "npx",
      "args": ["-y", "hatchik-mcp"],
      "env": {
        "HATCHIK_API_KEY": "YOUR_HATCHIK_API_KEY",
        "HATCHIK_API_URL": "https://api.hatchik.com"
      }
    }
  }
}

Tip: you can also drop this in a .cursor/mcp.json file at the root of a project to scope the connection to that project only.

3

Reload

Back in the MCP settings panel, you should see "hatchik" appear with a green dot. If it's red, click the refresh icon. If it's still red, check the API key for typos.

4

Test it

Open the chat panel (Cmd+L) and ask:

// You:
Are you connected to Hatchik? Show me my recent deploys.

Cursor's agent should call the Hatchik MCP and come back with a list of your last few deploys, plus their status. If it instead apologises or hallucinates, the MCP isn't connected — recheck the settings panel.

What this does, in plain English: Cursor's AI now knows about your live Hatchik project. When it writes code on your laptop, it can also push that code, watch the deploy land, and tell you if it broke anything — without you ever opening a dashboard. The money/data-risky actions still pop a confirm page in your browser before running.
W

Connect Windsurf to Hatchik

Works with Windsurf's Cascade agent.

1

Open the MCP config

In Windsurf: click the Cascade icon in the side panel, then the hammer/tools icon at the top of the Cascade pane, then Configure. Or edit the file directly:

~/.codeium/windsurf/mcp_config.json
2

Paste this in

Replace the placeholder with the key from your welcome email.

mcp_config.json 
{
  "mcpServers": {
    "hatchik": {
      "command": "npx",
      "args": ["-y", "hatchik-mcp"],
      "env": {
        "HATCHIK_API_KEY": "YOUR_HATCHIK_API_KEY",
        "HATCHIK_API_URL": "https://api.hatchik.com"
      }
    }
  }
}
3

Refresh Cascade

Back in the Cascade pane, click Refresh on the tools panel. Hatchik should appear in the available servers list with a green status.

4

Test it

Open Cascade and ask:

// You:
Are you connected to Hatchik? What's the URL of my preview deploy?

Cascade should hit the Hatchik MCP and reply with your preview URL. If it says it has no Hatchik tools, the config didn't load — check the file path and reload Windsurf.

What this does, in plain English: Cascade can now reach into your Hatchik project. Ask it to "ship the branch I just pushed" or "tell me why production is throwing 500s" and it does the work — same MCP standard as Claude and Cursor, just exposed through Cascade's interface.

Using something else?

Hatchik speaks the standard Model Context Protocol. Any MCP-capable client works the same way — find that client's MCP config file, paste the same hatchik server block, restart.
